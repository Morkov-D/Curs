# Техническое задание

## Проект
Локальная система учета и печати кодов маркировки «Честный Знак».

## Платформа
Python + Flet + локальная серверная БД + desktop-клиенты.

## 1. Цель проекта
Разработать локальную многопользовательскую систему для склада/производства, которая позволяет:
- загружать PDF-файлы с кодами маркировки «Честный Знак»;
- распознавать и извлекать из PDF Data Matrix-коды;
- сохранять коды и связанные данные в общей базе данных;
- предоставлять пользователям возможность выбирать товар, дату производства и доступное количество кодов для печати;
- формировать задания на печать;
- печатать выбранные коды на выбранный принтер с заданными параметрами;
- изменять статусы кодов в соответствии с бизнес-процессом;
- вести журнал действий пользователей, импортов и печатных заданий.

## 2. Общая архитектура
### 2.1 Архитектурная схема
- desktop-приложение на Flet, установленное на рабочих ПК;
- общая БД на локальном сервере склада;
- общая сетевая папка для PDF, временных файлов, логов, шаблонов и экспортов;
- PostgreSQL на локальном сервере;
- Python-логика приложения на клиентских ПК.

### 2.2 Режим работы
Система работает в локальной сети предприятия. Несколько пользователей с разных ПК работают с одной общей БД.

### 2.3 Поддерживаемый режим хранения данных
- Основной: PostgreSQL на локальном сервере.
- Опционально для тестов: SQLite в локальном файле на одном ПК.

## 3. Термины
- **Код маркировки** — уникальный Data Matrix для единицы товара.
- **PDF-импорт** — загружаемый PDF с кодами маркировки.
- **Партия** — набор кодов одного товара и одной производственной партии/даты.
- **Задание на печать** — сущность операции печати выбранного количества кодов.
- **Статус кода** — состояние кода: доступен, зарезервирован, напечатан, испорчен и т.д.

## 4. Функциональные требования
### 4.1 Авторизация и пользователи
Поддержка авторизации по логину и паролю.

Роли:
- Администратор
- Оператор импорта
- Оператор печати
- Просмотр / отчетность

Настройки пользователя:
- логин;
- пароль;
- роль;
- активность учетной записи;
- отображаемое имя.

Ограничения прав:
- только администратор управляет пользователями и глобальными настройками;
- только оператор импорта и администратор загружают PDF;
- только оператор печати и администратор создают задания на печать;
- только администратор выполняет аварийные действия.

### 4.2 Настройка подключения
При первом запуске доступен мастер настройки.

Администратор указывает:
- тип БД: PostgreSQL / SQLite;
- адрес/порт сервера БД;
- имя БД;
- логин/пароль;
- путь к общей сетевой папке;
- путь к локальной временной папке.

Система должна:
- проверять подключение к БД;
- создавать БД (при наличии прав);
- создавать таблицы при первой инициализации;
- создавать структуру каталогов хранения;
- сохранять конфигурацию локально на клиентском ПК.

### 4.3 Загрузка PDF
Оператор импорта выбирает PDF с локального ПК и загружает его.

При загрузке система:
- копирует PDF в общую папку;
- создает запись об импорте;
- присваивает уникальный идентификатор;
- фиксирует пользователя и время;
- запускает парсинг.

Для импорта сохраняются:
- имя файла;
- путь;
- дата/время загрузки;
- пользователь;
- статус обработки;
- количество найденных/сохраненных кодов;
- количество дублей;
- количество ошибок.

### 4.4 Парсинг PDF
Требования:
- поддержка векторных и растровых PDF;
- постраничная обработка;
- фиксация страницы нахождения кода;
- извлечение текстового содержимого;
- проверка на дубли;
- запись уникальных кодов;
- фиксация ошибок распознавания.

Для найденного кода сохраняются:
- `raw_code`;
- выделенные поля (если распознаны);
- товар;
- дата производства;
- ссылка на импорт;
- номер страницы;
- статус;
- время создания.

При смешанных товарах/партиях в одном PDF:
- авторазделение, если возможно;
- иначе статус ручной проверки.

### 4.5 Ручная проверка и корректировка
Экран ручной проверки импортированных кодов:
- просмотр кодов по импорту;
- фильтрация ошибок;
- ручная корректировка товара/даты/партии/статуса;
- удаление ошибочной записи;
- пометка кода как непригодного.

### 4.6 Учет товаров и партий
Товар:
- наименование;
- артикул;
- GTIN;
- категория;
- описание;
- активность;
- настройки печати по умолчанию.

Партия:
- ссылка на товар;
- дата производства;
- номер партии;
- примечание;
- дата создания.

Коды привязываются к товару, партии и дате производства.

### 4.7 Расчет доступного количества к печати
Оператор выбирает товар, дату производства и при необходимости партию.

Система показывает:
- общее количество;
- доступные к печати;
- зарезервированные;
- напечатанные;
- испорченные/выведенные.

В доступное количество входят только `available`.

### 4.8 Создание задания на печать
Параметры:
- товар;
- дата производства;
- партия (опционально);
- количество;
- принтер;
- шаблон;
- параметры печати;
- примечание.

Система:
- проверяет доступный остаток;
- создает задание;
- выбирает конкретные коды;
- резервирует коды;
- связывает коды с заданием;
- формирует материалы;
- отправляет на принтер.

Критично: выбор кодов + резервирование + создание задания в одной транзакции.

### 4.9 Генерация печатных материалов
- генерация Data Matrix из `raw_code`;
- этикетка по шаблону;
- служебные поля: товар, дата, партия, человекочитаемая строка;
- форматы: PDF, PNG (в перспективе ZPL/TSPL).

Требования:
- один код = одна уникальная этикетка;
- запрет повторения кода в одном задании;
- размер/отступы/ориентация задаются шаблоном и параметрами.

### 4.10 Печать
Система должна:
- показывать доступные принтеры текущего ПК;
- выбирать принтер по умолчанию;
- сохранять последний принтер пользователя;
- давать предпросмотр;
- отправлять сформированные файлы на принтер;
- фиксировать результат.

Настройки:
- принтер;
- копии;
- шаблон;
- формат;
- ориентация;
- масштаб;
- смещения;
- спецпараметры для профильных принтеров.

### 4.11 Статусы кодов
Обязательные статусы:
`imported`, `available`, `reserved_for_print`, `printed`, `reprinted`, `applied`, `spoiled`, `cancelled`, `error`.

Переходы:
- после успешного импорта: `available`;
- при создании задания: `reserved_for_print`;
- после печати: `printed`;
- при отмене без фактической печати: возврат в `available`;
- повторная печать — отдельный контролируемый сценарий.

### 4.12 Повторная печать
- доступна только уполномоченным;
- обязательная причина;
- запись в журнал;
- увеличение счетчика перепечаток;
- новый код не создается;
- используется тот же `raw_code`.

Причины:
- брак печати;
- смещение;
- повреждение этикетки;
- тестовая печать;
- замена носителя.

### 4.13 Журнал действий
Фиксируются:
- вход;
- загрузка PDF;
- запуск/завершение парсинга;
- создание задания;
- отправка на принтер;
- успешная печать;
- отмена задания;
- перепечать;
- ручное изменение статуса;
- ошибки.

Для записи: пользователь, дата/время, тип действия, объект, id объекта, сообщение.

### 4.14 Отчеты и поиск
Отчеты:
- список импортов;
- коды по товару/дате/партии/статусу;
- история печатных заданий;
- количество доступных/напечатанных/испорченных;
- действия пользователей.

Экспорт: CSV (и Excel опционально).

## 5. Нефункциональные требования
### 5.1 Технологии
- Python 3.11+;
- Flet;
- SQLAlchemy;
- Alembic;
- PostgreSQL;
- PyMuPDF / fitz;
- Pillow;
- библиотека чтения/генерации Data Matrix;
- печать через Windows-принтеры.

### 5.2 Развертывание
- сервер БД на локальном сервере склада;
- desktop-клиенты на рабочих ПК;
- общая папка хранения на сервере;
- конфиг подключения на каждом клиенте.

### 5.3 Производительность
Не менее:
- 5 одновременных пользователей;
- 500 000 кодов;
- PDF до 200 МБ;
- задание на печать до 5000 кодов.

### 5.4 Надежность
- критические операции транзакционны;
- дубли кодов запрещены;
- при ошибке печати сохраняется связь код↔задание;
- поддержка отката статусов.

### 5.5 Безопасность
- пароли только в виде хэшей;
- разграничение прав;
- аудит действий;
- отключение пользователя.
